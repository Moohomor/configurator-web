# SCORM 2004 пакет «3D-конфигуратор подвижного состава»

Приложение `example-main` обёрнуто в SCORM 2004 (4th Edition) course package
для загрузки в LMS (проверено совместимостью с WebSoft HCM — SCORM 2004
4ed и xAPI/CMI5 поддерживаются платформой; выбран SCORM 2004 4ed как
наиболее простой и надёжный вариант).

## Что входит в пакет

| Файл                          | Назначение                                                              |
| ----------------------------- | ----------------------------------------------------------------------- |
| `imsmanifest.xml`             | манифест SCO (SCORM 2004 4th Edition, все файлы перечислены)            |
| `index.html`                  | точка входа курса                                                        |
| `scorm/scorm2004.js`          | обёртка Runtime API `API_1484_11` (Initialize/Commit/Terminate и пр.)    |
| `scorm/course.js`             | трекер интеракций, подсчёт оценки и панель «Задания курса»               |
| `assets/`, `models/`, `tmh-previews/` | сборка приложения и 3D-ресурсы                                 |

## Оценка и завершение

Трекер отслеживает 7 заданий в конфигураторе:

| # | Задание                 | Тип      |
|---|-------------------------|----------|
| 1 | Выбрать модель          | обязат.  |
| 2 | Осмотреть модель в 3D   | обязат.  |
| 3 | Изучить детали модели   | обязат.  |
| 4 | Открыть информацию      | обязат.  |
| 5 | Настроить освещение     | обязат.  |
| 6 | Сменить текстур-пак     | бонус    |
| 7 | Запустить анимацию      | бонус    |

- `cmi.score.raw` = выполненные задания / 7 × 100 (0–100).
- `cmi.completion_status = completed`, когда выполнены все 5 обязательных.
- `cmi.success_status`: `passed` при ≥71 %, `failed` при 1–70 %, `unknown` при 0.
- Каждое задание записывается в `cmi.interactions` (`correct`/`incorrect`).
- Результат отправляется кнопкой «Завершить курс» либо автоматически при
  закрытии страницы.

## Сборка пакета

Требования: Node.js 20+, npm 10+.

```
npm run install:all        # установка зависимостей (один раз)
npm run build:scorm        # сборка библиотеки, приложения и пакета
```

Результат:
- `scorm-package/` — распакованный курс (для отладки);
- `configurator-web-scorm2004.zip` — готовый SCORM 2004 пакет для загрузки в LMS.

Вручную: `npm run build && node scripts/package-scorm.mjs`.

## Изменения исходников (для работы в iframe LMS)

1. `configurator-main/.../ModelSelector.vue`, `ModelViewer.vue` —
   пути к моделям/текстурам/превью резолвятся от `document.baseURI`
   вместо `window.parent.location.href` (в iframe LMS родитель — страница
   курса в системе, а не контент; при кросс-домене чтение было б ошибкой).
2. `example-main/vite.config.js` — `base: './'` (относительные пути сборки).
3. `example-main/src/main.js` — пути моделей нормализуются в относительные
   (`/models/...` → `models/...`).
4. `example-main/index.html` + `example-main/public/scorm/*` — подключение
   SCORM-обёртки и трекера.

## Локальное тестирование

- Без LMS: `npm --prefix ./example-main run preview` — приложение работает,
  панель «Задания курса» показывает «вне LMS».
- С имитацией LMS: раздать корень репозитория статическим сервером
  (`python -m http.server 5000`) и открыть
  `http://localhost:5000/scorm-test/lms-simulator.html` — видна запись
  `cmi.*`-элементов в режиме реального времени.
- Автотест логики SCORM: `node scripts/smoke-test.cjs` (36 проверок).
