# SCORM 2004 пакет «3D-конфигуратор подвижного состава»

Приложение собрано в SCORM 2004 (4th Edition) course package для загрузки в
LMS. Каждая модель с 3D — отдельный урок, то есть отдельный `<item>` в дереве
курса: до неё можно дойти прямо из меню LMS, минуя каталог.

## Что входит в пакет

| Файл | Назначение |
| ---- | ---------- |
| `imsmanifest.xml` | манифест: один `<resource>` на каждый пункт меню курса |
| `index.html` | «Каталог моделей» — обзор курса и общий прогресс |
| `lesson-<id>.html` | точка входа урока, своя SCO-сессия и своя запись в журнале LMS |
| `embed-<id>.html` | лёгкий вьюер для вставки в **сторонний** курс; в собственном курсе не используется (встраивать его тоже не надо — см. «Контент-пакет») |
| `assets/` | бандл приложения; `ModelViewer-*.js` (three.js) грузится только на уроке |
| `models/`, `tmh-previews/` | 3D-модели, текстуры, превью |

## Уроки и навигация

Меню курса: «Каталог моделей» + 8 уроков, у каждого свой `href` на
`lesson-<id>.html`. Проверено на WebSoft HCM: `<parameters>` там не работает
(импорт проходит, но все уроки молча открывают каталог), поэтому вариант с
одним SCO на весь курс удалён — на каждый пункт приходится отдельный SCO.

**Внутри урока нет кнопки возврата в каталог, и нет переходов между
документами.** Каталог лежит в другом HTML-файле, и переход к нему изнутри
SCO — это перезагрузка документа в SCO-фрейме: новая загрузка зовёт
Initialize второй раз в одной сессии. Для SCORM это нарушение протокола, и
после него LMS считает попытку закрытой — уроки перестают открываться.
Навигация между уроками — меню курса.

По той же причине внутри LMS карточки галереи и список уроков в боковой
панели — обычный текст, а не ссылки: кажущаяся возможность уйти в урок из
каталога только сбивает с толку. Вне LMS переходы по карточкам сохранены, так
что галереей можно пользоваться и без LMS (`npm run dev`, `npm run preview`).

## Структура манифеста

Один `<resource>` на каждый пункт меню курса: каталог плюс отдельный
`lesson-<id>.html` на каждый урок. Никаких флагов сборки.

Вариант с одним SCO на весь курс и `<parameters>?lesson=<id>` у каждого
`<item>` проверялся и удалён: WebSoft HCM `<parameters>` игнорирует — импорт
проходит без ошибок, но все пункты меню открывают каталог. Отличить такой
отказ от рабочего пакета можно только вручную, поэтому вариант не оставлен.

## Оценка и задания

Задания объявлены данными в `src/scorm/lessons.ts` и применяются к каждому
уроку отдельно:

| id | Задание | Тип | Условие |
| -- | ------- | --- | ------- |
| `open` | Открыть урок | обязательное | 3D-сцена загрузилась |
| `part` | Выбрать деталь | обязательное | выбрана деталь в сайдбаре или кликом по сцене |
| `animation` | Запустить анимацию | дополнительное | засчитывается, только если в модели реально есть анимация |

Наличие анимации определяется на лету по загруженной сцене, а не флагом в
каталоге: у редуктора анимация есть, у тележки — нет, и лишнее задание у неё
не появляется.

Правила подсчёта (`src/scorm/lessons.ts`):

- `cmi.score.raw` = выполненные **обязательные** задания / все обязательные
  задания в зоне ответственности SCO × 100. Знаменатель фиксирован: два
  обязательных задания на урок. Дополнительное задание (анимация) в оценку
  не входит — оно есть не у всех моделей, и с ним «2 из 16» превращалось бы
  в «2 из 17» просто от того, что обучающий посмотрел вторую модель. Правая
  часть дроби обязана быть постоянной, иначе прогресс не отслеживается.
- `cmi.completion_status = completed`, когда выполнены все обязательные задания.
- `cmi.success_status`: `passed` при ≥ 67 % (`PASS_PERCENT`), `failed` при частичном выполнении, `unknown` при 0.
- Каждое задание пишется в `cmi.interactions` (`correct` / `incorrect`), id вида `loco-ep20.open`.
- Прогресс хранится в `cmi.suspend_data` и восстанавливается при следующем запуске.
  При нехватке места (лимит 4096 символов) отбрасываются самые давние уроки,
  а строка не обрезается: обрезанный JSON не читается, и прогресс пропал бы целиком.

**Оценка уходит в LMS постоянно, а не по кнопке «завершить».** На каждое
выполненное задание обновляются `score`, `completion_status`, `success_status`,
`location` и `interactions`, и сразу следует `Commit`. Кнопки «Завершить» в
интерфейсе нет: она ставила `Terminate` посреди работы и замораживала учёт —
задания, выполненные после неё, в отчёт уже не попадали. Сессию закрывает
LMS, когда обучающий уходит из урока.

Границы оценки объявляются сразу при `Initialize` (`score.min`, `score.max`,
`completion_status`). HCM читает их один раз — при первом обращении к score;
узнать оценку можно только после первого задания, и к тому моменту LMS уже
считает, что максимум равен нулю.

**Зона ответственности SCO** определяется при запуске:

- SCO открыт как отдельный урок (`lesson-<id>.html`, в коде есть `window.__LESSON__`) — отвечает только за этот урок: 0 %, 50 % или 100 % (два обязательных задания);
- SCO открыт как каталог (`index.html`) — отвечает за весь курс: 16 обязательных заданий на 8 уроков.

Сводный балл за курс в LMS не собирается автоматически: для этого нужен
`adlseq`-трек в манифесте.

`Terminate` **не вызывается** при `visibilitychange`: документ SCO уходит в
фон при alt-tab, клике на окно LMS и открытии соседней вкладки. Если на этом
событии закрывать сессию, LMS дальше отклоняет все `SetValue`, и обучающий
теряет прогресс. Сессия закрывается только на `pagehide` / `beforeunload` —
то есть когда документ действительно уничтожают.

## Сборка пакета

Требования: Node.js 20+, npm 10+, Python (для ZIP).

```powershell
npm.cmd install            # зависимости (один раз)
npm.cmd run build:scorm    # приложение + SCORM-пакет
npm.cmd run build:embed    # приложение + контент-пакет (встраивание)
```

Два независимых режима упаковки, оба читают один и тот же `dist/`:

| Режим | npm | Результат |
| ----- | --- | --------- |
| `scorm` (по умолчанию) | `build:scorm` | `scorm-package/` + `configurator-web-scorm2004.zip` — курс для импорта в LMS |
| `embed` | `build:embed` | `content-package/` + `configurator-content.zip` — контент для встраивания в чужой курс (см. следующий раздел) |
| `all` | — | оба пакета (в CI) |

Вручную: `npm.cmd run build` → `node scripts/package-scorm.mjs <режим>`,
где режим — `scorm` / `embed` / `all`.

> ZIP создаётся только Python `zipfile`. `Compress-Archive` и .NET `ZipFile`
> пишут записи с обратными слэшами, и LMS на Linux такой пакет не импортирует.

## Контент-пакет и встраивание в сторонний курс

Помимо собственного курса приложение поставляется материалом для чужого
курса: модели вставляются iframe'ом посреди текста, как картинки, и
отдельными страницами — как полноценные уроки.

`configurator-content.zip` — тот же `dist`, но без манифеста, и в каждую
HTML-точку входа упаковщик вшивает

```html
<script>window.__CONTENT_EMBED__ = true;</script>
```

Этот флаг переключает приложение в режим `embedMode()`:

- страница поднимает `EmbedRuntime`, который **никогда** не ищет
  `API_1484_11` и не вызывает `Initialize`/`Terminate` — чужая SCO-сессия
  не трогается вообще;
- прогресс заданий пишется в отдельный ключ `localStorage`
  (`configurator:embed-progress`), в LMS не уходит и не смешивается ни
  с прогрессом собственного курса, ни с локальным режимом разработки;
- смена документа не запрещена: сессии нет, второй `Initialize` не
  грозит (сейчас такой переход недостижим из UI — кнопки возврата в
  каталог в уроке нет, — но запрет снят на случай, если она появится).

У `embed-<id>.html` ключ свой — `configurator:embed-viewer-progress`.
Вьюер вставлен «картинкой», панели заданий у него нет, но трекер всё
равно отмечает загрузку модели и выбор детали; на общем ключе эти
невидимые отметки потом показались бы в полном `lesson-<id>.html` как
«уже выполненные задания».

Две точки входа для вставки:

| Страница | Что показывает |
| -------- | -------------- |
| `embed-<id>.html` | лёгкий вьюер: сцена, текстуры, свет, анимации, инфо-панель; без шапки урока и без панели заданий |
| `lesson-<id>.html` | полный урок как в собственном курсе: шапка, задания, прогресс |

Файлы загружаются в материалы стороннего курса, а в текст урока
вставляется iframe — все внутренние пути относительные, каталог может
лежить где угодно. Подробные примеры разметки — в `README.md`.

**Встраивать можно только файлы из контент-пакета.** `lesson-<id>.html`
из SCORM-пакета не содержит флага: внутри чужого SCO он нашёл бы
`API_1484_11` в родителях и открыл чужую сессию своим `Initialize` —
после второго `Initialize` в одной сессии LMS считает попытку закрытой,
и ломается чужой курс. Флаг намеренно вшит в файл, а не передаётся
адресом: автор стороннего курса не может его забыть. Аварийный
эквивалент, если файлы пришлось взять из SCORM-пакета, — параметр
`?embed=1` у адреса страницы.

## Локальное тестирование

- **Без LMS**: `npm.cmd run dev` или `npm.cmd run preview`. Панель заданий
  показывает «Конфигуратор запущен вне LMS», прогресс живёт в `localStorage`.
- **Имитация LMS**: `python -m http.server 5000` в корне репозитория и
  `http://localhost:5000/scorm-test/lms-simulator.html` — видно запись
  `cmi.*` в реальном времени.
- **Автотесты**: `npm.cmd test` — Playwright гоняет собранный `dist/`: SCO
  открывается во вложенном iframe, рядом подставлен фейковый `API_1484_11`,
  проверяется инициализация, `suspend_data`, отправка результата и то, что
  приложение **не создаёт собственного iframe** (`page.frames().length === 2`).

## Правила, которые нельзя нарушать

1. **Приложение не создаёт внутренний iframe.** Раньше библиотека монтировала
   весь UI в собственный `<iframe>` с инъекцией стилей; отсюда была трёхуровневая
   вложенность (LMS → SCO → iframe) и необходимость нюхать DOM. Сейчас UI
   рендерится прямо в документе SCO, стили идут обычным CSS-конвейером Vite.
2. **Пути к моделям и текстурам — относительные, от `document.baseURI`.**
   Внутри LMS контент раздаётся из произвольного подкаталога; `base: "./"` в
   `vite.config.ts` и относительные пути в `src/catalog/models.json` — обязательны.
   Обращения к `window.parent.location.href` недопустимы: родитель — это страница
   системы, и в кросс-домене чтение упало бы.
3. **Поиск `API_1484_11` вверх по родительским окнам — требование SCORM**, а не
   костыль: LMS прячет API в родительском окне. Цепочка обрывается на
   кросс-доменном окне — это ожидаемо, не ошибка.
4. **`Initialize` вызывается один раз за SCO-сессию.** Отсюда запрет на
   перезагрузку документа при навигации между уроками.
5. **Манифест генерируется из `dist/`.** Новые модели, текстуры и превью попадают
   в пакет сами; руками `imsmanifest.xml` не править.
6. **Имена файлов в пакете — ASCII.** Кириллица в имени файла ломает импорт на
   Linux-LMS (модель редуктора поэтому называется `models/reductor/reductor.glb`).
7. **Контент для стороннего курса никогда не трогает SCORM API.** Режим
   встраивания выбирается только по явному признаку (`window.__VIEWER__`,
   `window.__CONTENT_EMBED__`, `?embed=`), но никак не по наличию
   `API_1484_11`: встроенный фрейм всегда лежит внутри SCO чужого курса,
   и «API найден» означает «найдена чужая сессия». `EmbedRuntime` не вызывает
   `Initialize` ни при каких условиях — иначе нарушение протокола в чужой
   сессии ломает чужой курс.
